# おてほん

ピアノの楽譜の写真やPDFを読み取り、楽譜どおりに鳴らす、Mac用のローカルWebアプリ。

## 必要なもの

- macOS
- [uv](https://docs.astral.sh/uv/)
- [Claude Code](https://claude.com/claude-code)（`claude` を起動して `/login` 済みであること。校正に使う）
- インターネット接続（ピアノ音源と描画ライブラリをCDNから読み込む）

## 起動

```bash
uv run server.py
```

ブラウザで http://localhost:8765 を開く。

## 使い方

1. 楽譜の写真（JPEG・PNG・HEIC）かPDFを画面に置き、曲名を付けて「読み取る」。
2. 読み取りが終わると楽譜が出る。再生ボタンかスペースキーで鳴らす。
3. 本と違って聞こえるところは、校正欄に言葉で書くと直る（例: 12小節目の右手、最初のファはシャープ）。

再生では、テンポ、右手・左手だけの再生、小節範囲のループ、メトロノームが使える。
リピート、1番・2番括弧、D.C.・D.S.・Fine・Coda は楽譜どおりの順にたどる。

## しくみ

1. [homr](https://github.com/liebharc/homr) が画像を MusicXML にする（ローカルで実行）。
   homr が音符の位置を五線の上で測った結果は、オクターブの読み違いを直すのに使う。
2. Claude Code が写真と見比べて MusicXML を直す（サブスクリプションの範囲で実行）。
   連符は Claude が「何個を何個ぶんの長さで弾くか」だけを書き、音の長さはコードが計算する（5連符や13連符は割り切れないため）。
3. 直したデータを五線譜に描き直し（Verovio）、写真の段と上下に並べて Claude が1段ずつ見比べる。
   描き直しには連桁と連符の数字を付け、写真と同じ形で比べられるようにする。
   食い違いは別の Claude がデータと写真で確かめて直し、直した段をもう一度見比べる（3回まで）。
   判断がつかなかった小節は、楽譜に朱の点線で示す。
4. ブラウザが OpenSheetMusicDisplay で楽譜を描き、Tone.js で鳴らす。

曲は `library/` に保存される。

## 制約

- ピアノ譜（上下2段の大譜表）専用。それ以外の楽譜はうまく動かない可能性が高い。
  音色は常にピアノで、上の五線を右手、下の五線を左手として扱う。パートが複数ある楽譜は最初のパートしか正しく扱われず、
  タブ譜・打楽器譜は読み取れない。
- 認識は完全ではない。Claude が推測で入れた値（数字のないテンポなど）は校正欄に「推測」と出る。
- サーバーは `127.0.0.1` だけで待ち受ける。認証はないので、他の端末には公開しないこと。
- 描き直しての見比べにも見落としはある。わざと6件の間違いを入れた試験では、5件を直し、1件を見落とした。
- 校正と見比べで、1ページあたり数分かかり、Claude を10回前後呼ぶ。サブスクリプションの利用上限に達すると、
  その先は読み取ったままの楽譜になる（校正欄に理由が出る）。

## 読み取りの出来を測る (開発用)

正解の分かっている楽譜を読み取らせて、間違いを数える。変更が良くなったかどうかを数字で見るためのもの。
対象は PDF の楽譜 (きれいな印刷譜)。試した策と結果は [docs/experiments.md](docs/experiments.md) にまとめている。

```bash
brew install --cask musescore                 # 正解を MuseScore で PDF にするのに使う
uv run --with music21 python make_truth.py    # 正解を作る (初回だけ)
uv run python bench.py --selftest             # 採点そのものの検算
uv run python bench.py raw fixed              # 校正なし。fixed はオクターブの自動修正あり。1回目は OMR に時間がかかる (結果は取っておく)
uv run python bench.py full --yes-full        # 校正まで本番どおり。Claude を使う (サブスクリプションを消費する) ので、必要なときだけ
```

- `bench/truth/*.musicxml` が正解。music21 のコーパスから `make_truth.py` で作る (20曲)。
  コーパスの権利は別なので `bench/` は git に入れない。`test_` で始まる曲は `--test` を付けたときだけ測る (改善の判断に使わない)。
- 正解を Verovio (字体を曲ごとに替える) と MuseScore 4 の PDF の2通りでページ画像にし、
  アプリが PDF を取り込むときと同じく横2000px・JPEG 品質0.92 で読み取る。
- 採点は「鳴る音」で行う。小節ごとに両手の音 (高さ・位置・長さ) が全部合っていれば正解。
  音の食い違いは、オクターブ違い・半音違い (臨時記号)・その他の高さ違い・長さ違い・位置違い・欠け・余りに分ける。
  間違っているのに「確かめきれなかった」印がない小節 (silent) も数える。人が確かめなくてよいのは、これが 0 のとき。
- 結果は `bench/work/results_<段階>[_<label>].json` に、毎回の合計は `bench/work/history.jsonl` に残る。
- リピート、テンポ、強弱、スラー、連桁は採点しない。

### これまでに測って分かったこと (写真風の画像も使っていたころ)

正解つきの7曲 (12ページ、193小節、2970音) で測った。校正つきの測定は1回ずつなので、数小節の差は Claude の揺れと区別できない。

- homr だけ (校正なし) で、きれいな画像は 160/193 小節、写真風の画像は 157/193 小節が合う。
  間違いの9割以上はリズム (位置・長さの違い、音の欠け・余り。連符で目立つ) で、音の高さの間違いは1割に満たない。
- 校正と見比べは効く。モーツァルト K.545 とショパンのマズルカ (きれいな画像、65小節) は 57 → 65 小節。
  C.P.E. バッハ H.186 (写真風、32小節。5連符・13連符がある) は 21 → 25〜26 小節。
- オクターブの自動修正 (`measure.py`) は、校正なしで1小節良くなり、悪くなった小節はない。
  本物の写真14ページでは20音を正しく直し、1音を誤って動かした (8va の下の音)。残している。
- 校正の最初に「先に見る場所」を伝える手がかりを2種類試して、外した。
  1つは音符の位置の測定がデータと食い違う音、もう1つは音の長さを足すと拍子に合わない小節。
  C.P.E. バッハで、手がかりなしは 26/32 小節、ありは 25/32 小節で、差が出なかった。
  位置の測定が食い違うと言った音は、校正が写真で確かめるとほとんどデータのほうが合っていた。
  拍子に合わない小節は、手がかりがなくても校正が自分で見つけて直していた。
- 校正のあとに残る間違いは連符のリズムで、ありでもなしでも同じ小節 (4・5・17・31) を間違えた。
  次に手を入れるならここ。音の高さを確かめる仕組みを足しても、もう伸びない。
- 残った間違いを画像で見ると、原因は2つあった。どちらも直した。
  - 見比べ用の描き直しに連桁がなく、32分音符と64分音符の違い (線が3本か4本か) を写真と比べられなかった。
    連桁と連符の数字を描くと、見比べが線の本数の違いを指摘するようになった。これだけでは正解率は変わらなかった (28/32、揺れの範囲)。
  - 5連符・13連符・64分音符の長さが、1拍の分解能で割り切れず書けなかった。見比べが気づいても直せなかった。
    Claude には連符の割り方と音符の種類だけを書かせ、長さはコードが書くと 30/32 小節 (804音中799音)。
    連符の2小節は、それまで3回測って3回とも間違えていた小節。
- 上の2つを入れたあと、7曲を校正つきで通すと 184/193 小節 (2970音中2955音)。校正なしは同じ画像で 154/193 小節。
  モーツァルト、ショパン、メープルリーフ・ラグ、菩提樹は全小節が合った。残りは C.P.E. バッハ 30/32、
  シェーンベルク op.19-2 が 8/9、op.19-6 が 4/10。op.19-6 は加線の多い高い音と、小節をまたぐタイの長さが残る。
- 実物の写真でも試した。3連符のページ (エリーゼのために) は以前の結果と全音が一致した。
  The Story of Us では、homr が同じ音の続くところに写真にない弧を読み、それがタイになって2小節に残った。
  見比べがその段を見逃したため。同じ段の見比べだけを繰り返すと、連桁つきの絵で13回中10回、旗の絵で13回中12回見つけた。
  差は偶然の範囲で、見比べは1段につき1〜2割の確率で見逃す、というのが実力。
- 効かなかった策と効いた策の違い: 「どこを見るか」を教えても変わらず、「見えたものを書けない・比べられない」を直すと変わった。
- 利用上限に当たって待つあいだに Mac がスリープすると、待ち時間が延びる。30秒ずつ待つようにして直した。
